# Кикшеринг — запуск для преподавателя

Начните с этого файла или откройте START_HERE.html. Это локальный стенд из BFF/фронтенда и пяти Java-микросервисов. **IDEA и Docker не требуются.** Для первого запуска готовые WAR уже находятся в dist; Maven и Node.js для этого не нужны.

## 1. Что должно быть установлено

- **JDK 17** (именно JDK). Проверка: `java -version`.
- **PostgreSQL 16+** и клиент psql. Linux-скрипт также совместим с PostgreSQL 13–15; для одинакового порядка запуска рекомендуем 16+. Сервер PostgreSQL должен быть запущен.
- **Python 3.9+** (рекомендуется 3.11+). Linux: `python3 --version`; Windows: `py -3 --version`.
- Распакованный **Apache Tomcat 10.1**, полный бинарный архив с bin/bootstrap.jar и lib/. Скачать: https://tomcat.apache.org/download-10.cgi . Устанавливать службу Tomcat и вручную менять server.xml не надо. Tomcat 9 и 11 этим запуском не поддерживаются.

При первом PDF библиотека может строить кэш шрифтов; генерация ограничена тайм-аутом 60 секунд. Кэш сохраняется в local-run/stand/documents/cache и используется при следующих запусках.

Шрифт для PDF уже включён: assets/DejaVuSans.ttf с лицензией. Интернет для работы фронтенда/шрифтов/PDF не нужен. Интернет может требоваться только для установки программ, загрузки Tomcat или повторной Maven-сборки исходников.

### Ubuntu/Debian — если программы ещё не установлены

```bash
sudo apt update
sudo apt install openjdk-17-jdk postgresql postgresql-client python3
sudo systemctl start postgresql
```

### CachyOS/Arch — если программы ещё не установлены

```bash
sudo pacman -S --needed jdk17-openjdk postgresql python
```

Только при **первой установке PostgreSQL**, если кластер /var/lib/postgres/data ещё не инициализирован:

```bash
sudo -iu postgres initdb --locale=C.UTF-8 -D /var/lib/postgres/data
```

На существующем кластере initdb не выполнять. Затем:

```bash
sudo systemctl start postgresql
```

### Windows

Установить JDK 17, Python 3 и PostgreSQL обычными установщиками. При установке PostgreSQL запомнить пароль администратора postgres и выбранный порт. Tomcat 10.1 распаковать, например в `C:\Tools\apache-tomcat-10.1.61`. Проект удобно распаковать в короткий путь, например `C:\kicksharing`.

Проверка команд: `java -version`, `py -3 --version`. Если psql не в PATH, скрипт пробует найти его в Program Files/PostgreSQL; можно указать путь флагом --psql.

## 2. Распаковать проект и открыть терминал в его корне

В корне должны лежать этот README, pom.xml, scripts/, dist/, services/, src/. Не запускать из отдельной папки src. На машине должно быть свободно около 3 ГБ RAM для шести JVM и PostgreSQL.

В архиве **нет чужих БД, паролей, JWT-ключей и local-run**. Они создаются на вашей машине. Если раньше запускали другой стенд/IDEA, остановите его: HTTP-порты 8080–8085 должны быть свободны.

## 3. Создать все пять БД, ключи и окружение

### Linux (Ubuntu/CachyOS), из корня проекта

```bash
python3 scripts/stand.py prepare --pg-port 5432 --database-prefix kicksharing_teacher_
```

Обычный пользователь запускает команду **без sudo перед python**. Скрипт сам запросит sudo, чтобы выполнить административные SQL-команды от системного пользователя postgres. Пароль sudo — пароль вашего пользователя Linux.

### Windows, PowerShell из корня проекта

```powershell
py -3 scripts/stand.py prepare --pg-port 5432 --database-prefix kicksharing_teacher_
```

Будет запрошен пароль PostgreSQL-пользователя postgres из установщика. Это не пароль пользователя сайта.

Если сервер БД использует другой порт, например **7689**, во всех командах prepare замените 5432 на него. При другом администраторе БД добавьте `--pg-user имя`. Для Linux с TCP-паролем вместо sudo добавьте `--password-auth`. При нестандартном расположении программ:

```text
--psql /полный/путь/к/psql --java /полный/путь/к/jdk-17/bin/java
```

На Windows указывайте пути с .exe в кавычках. Нельзя путать версию pgAdmin с версией сервера PostgreSQL.

Команда создаёт:

```text
kicksharing_teacher_user
kicksharing_teacher_moderation
kicksharing_teacher_scooter
kicksharing_teacher_ride
kicksharing_teacher_documents
```

BFF отдельная БД не нужна. Загружаются схемы, примерные самокаты и все миграции, включая отзывы. В local-run/ создаются ключи RSA, общий ключ интеграции и настройки каждого сервиса. Ничего вручную переносить в Environment variables/VM options не требуется — скрипт запуска прочитает JSON-файлы сам.

Повторять prepare можно с **теми же параметрами и сохранённой local-run**: данные и ключи сохраняются, применяются только недостающие миграции. Linux-скрипт создаёт отдельную служебную роль; существующим пользователям пароль не сбрасывает. Чужие БД с другим владельцем автоматически не переприсваивает. Если префикс уже занят другим проектом, используйте новую распакованную папку и другой уникальный префикс. Не удаляйте рабочую local-run ради повторного запуска.

## 4. Автоматически поднять все сервисы

Подставьте **свою реальную папку Tomcat**, а не путь к bin/ и не путь к проекту.

### Linux

```bash
python3 scripts/stand.py start --tomcat-home "/путь/к/apache-tomcat-10.1.61"
```

### Windows

```powershell
py -3 scripts/stand.py start --tomcat-home "C:\Tools\apache-tomcat-10.1.61"
```

Скрипт проверяет готовые WAR и соответствие исходникам, создаёт шесть отдельных конфигураций внутри local-run/stand/, разворачивает каждое приложение как ROOT с контекстом `/`, выставляет HTTP-порты, отключает конфликтующие shutdown-порты и запускает JVM с ограничением памяти. Все HTTP-коннекторы слушают только 127.0.0.1. Команда ждёт готовности приложений и возвращает терминал; окна IDEA/Tomcat вручную открывать не надо.

Успешный итог: `Ready: http://localhost:8080/ ...`. Проверка состояния:

```bash
python3 scripts/stand.py status
```

Windows: вместо `python3` используйте `py -3`. HTTP=401 у Scooter/Documents в status **ожидаем**: это проверка того, что защищённая ручка работает без токена. `ready=True` и `managed=True` должны быть у всех шести.

| Приложение | HTTP-порт | Основной адрес |
| --- | --- | --- |
| BFF + пользовательский сайт | 8080 | http://localhost:8080/ |
| User | 8081 | API пользователей |
| Moderation | 8082 | http://localhost:8082/admin/users.html |
| Scooter | 8083 | API самокатов |
| Ride | 8084 | API поездок и публичных отзывов |
| Documents | 8085 | API PDF и истории документов |

На служебных портах нет отдельной пользовательской главной страницы. При вводе API-адреса в браузере возможна страница «Служебный адрес» с HTTP 403; корни Scooter/Documents могут дать HTML 404. Это не проверка работы пользовательского сайта. Для JSON используйте Postman/curl с `Accept: application/json` и нужным Bearer-токеном.

## 5. Создать пользователя и администратора для демонстрации

После Ready выполните:

```bash
python3 scripts/stand.py demo
```

Windows:

```powershell
py -3 scripts/stand.py demo
```

Введите и подтвердите пароль от 8 символов, максимум 72 байта UTF-8. Пароль **не записывается в файл**. Команда создаёт/проверяет:

- **demo.user** — обычный пользователь;
- **demo.other** — второй обычный пользователь для проверки доступа к чужим данным;
- **demo.admin** — администратор.

Пароль всех трёх аккаунтов — **тот, который вы только что ввели**. Общего встроенного пароля нет. Команда проверяет авторизованное чтение всех шести сервисов, а также назначает/проверяет ADMIN через штатную CLI-команду User. Это заменяет ручные UPDATE в pgAdmin. При существующем аккаунте с другим паролем пароль не сбрасывается: нужно указать прежний либо создать другой набор, например `python3 scripts/stand.py demo --user-login teacher.user --other-login teacher.other --admin-login teacher.admin`. Команда откажется работать, если этот пакет не запущен его собственным start, чтобы не менять случайно другой стенд на тех же портах.

Для своих аккаунтов можно использовать регистрацию сайта. Все публичные регистрации создают USER. Возраст при регистрации — не менее 16 лет, ФИО — 2–4 слова с заглавных букв, кириллица либо латиница без смешения алфавитов.

## 6. Что открыть и проверить

Откройте **http://localhost:8080/**, после обновления исходников очистите кэш Ctrl+Shift+R.

1. Войти как demo.user с выбранным паролем, открыть профиль, каталог и историю.
2. Разрешить геолокацию: показаны ближайшие READY. При запрете показан общий каталог без расстояний. Демонстрационные координаты самокатов взяты из БД и могут быть далеко от вашего города; радиус поиска не ограничен. Для проверки можно использовать тестовую геолокацию браузера, совпадающую с координатами выбранного самоката.
3. Начать поездку на свободном самокате, обновить позицию, завершить. Без геолокации старт использует позицию самоката, а завершение по сохранённой позиции требует отдельного подтверждения.
4. Оплатить: базовый тариф 50 ₽ за старт + 8 ₽ за начатую минуту, минимум 58 ₽. **Оплата учебная, реальных списаний нет.**
5. Оставить отзыв с двумя оценками и комментариями; обновить страницу и проверить реальную анонимную ленту отзывов на главной.
6. Скачать чек оплаченной поездки и историю PDF. Открыть файлы, проверить русские буквы, сумму и номер поездки/самоката.
7. Выйти. Открыть **http://localhost:8080/login.jsp** и войти как demo.admin с тем же выбранным паролем: переход в панель 8082 происходит автоматически. Для одновременной проверки USER/ADMIN используйте разные профили браузера/инкогнито.
8. В панели проверить список, фильтры, блокировку/разблокировку demo.user. USER не может читать список пользователей, справочник модерации или чужой профиль. Заблокированный USER может завершить и оплатить уже начатую поездку, но не начать новую. Уведомление о блокировке PDF доступно во время блока.

При действующей USER-сессии login.jsp открывает кабинет, а не другую форму входа. Чтобы сменить аккаунт на ADMIN, сначала нажмите «Выйти». Существующая ADMIN-сессия позволяет повторно войти в панель без повторного ввода пароля.

Полные актуальные REST-контракты: **docs/API_CONTRACTS.md** (все 60 операций, DTO, права, три PDF, GPS и отзывы).

Полная проверка: **docs/FULL_API_URL_CHECKLIST.md** — 331 пункт и 60 операций API. Результаты можно заполнить в CSV. Коллекция Postman в docs/ — справочник отдельных запросов, выполнять по предусловиям: сначала создать поездку, затем завершить/оплатить и только после этого получать чек. Не запускать все запросы подряд с одним пустым rideId.

## 7. Остановить и запустить снова

```bash
python3 scripts/stand.py stop
```

Windows: `py -3 scripts/stand.py stop`.

Останавливаются только процессы этого пакета. Базы, ключи, аккаунты, поездки, отзывы и документы сохраняются. Для следующего запуска достаточно start с путём к Tomcat; prepare и demo заново не обязательны.

Не переносите папку работающего стенда. Для переноса сначала stop, затем перенести весь проект вместе со своей local-run и повторить prepare с прежними параметрами: он обновит абсолютные пути к ключам/шрифту. После этого start. Перенос с данными БД на другой компьютер — отдельная операция backup/restore PostgreSQL; ZIP исходников сам по себе прежние пользовательские данные не содержит.

## 8. Если что-то не запустилось

- **Port ... is busy:** остановить прежние конфигурации IDEA/старый стенд на 8080–8085. Скрипт не завершает чужие процессы.
- **БД/версия/пароль:** проверить настоящий host/port сервера, его версию `SHOW server_version;` и доступ postgres. Для PostgreSQL 18 на порту 7689 указать `--pg-port 7689`. Linux sudo-пароль, PostgreSQL postgres-пароль и пароль аккаунта сайта — разные вещи.
- **Миграция/поля review:** повторить prepare с прежними параметрами. Не редактировать уже применённые SQL-файлы. На свежем стенде миграции выполняются автоматически от правильного владельца БД.
- **Sources changed / Missing/changed WAR:** исходники/сборки изменены. Выполнить build из следующего раздела. Скрипт намеренно не запускает незаметно старый WAR поверх новых исходников.
- **Startup timed out / приложение exited:** открыть `local-run/stand/<имя сервиса>/logs/console.log`. Там же отдельные журналы Tomcat. Команда start при ошибке останавливает собственные частично запущенные процессы, не сообщает ложную готовность.
- **JWT_PUBLIC_KEY_PATH / public.pem:** повторить prepare из текущей папки. Нужен абсолютный путь к публичному ключу того же комплекта, который использует User. Не создавать отдельные RSA-ключи для Documents. Папки проекта и local-run должны принадлежать вашему пользователю и быть доступны запускаемому Java.
- **PDF/шрифт:** bundled assets/DejaVuSans.ttf должен существовать, prepare сам записывает его абсолютный путь. Файл .pdf при ошибке API не должен содержать HTML/JSON.
- **Геолокация:** открывать через localhost на той же машине; при отказе использовать общий каталог и подтверждение сохранённой позиции. Это не подтверждение фактической парковки по GPS.
- **Неверная роль:** выйти и войти заново; demo создаёт/проверяет роль ADMIN. Назначить роль в форме регистрации нельзя.

При ошибке сохраняйте имя сервиса, фактический HTTP-ответ и Caused by. Не пересылайте local-run, пароли, токены и private.pem.

## 9. Исходники, повторная сборка и тесты

Исходники и pom.xml всех шести приложений включены. Если меняете Java/JSP/JS/CSS, остановите стенд и пересоберите через Maven (Maven должен быть установлен, интернет для зависимостей может понадобиться):

```bash
python3 scripts/stand.py build
```

Команда последовательно собирает шесть приложений, обновляет dist и контрольные суммы исходников/WAR. Это быстрая сборка с -DskipTests. Затем снова start. При изменении схем добавлять новую миграцию и выполнить prepare; старые применённые SQL не менять.

Для проверки Java можно выполнить `mvn verify` в корне и отдельно в каждой папке services/<имя>. HTTP-тесты User дополнительно используют TEST_DB_URL/TEST_DB_USER/TEST_DB_PASSWORD и временную схему. Для браузерных тестов нужны необязательные Node.js 22+, npm ci и Playwright/Chromium; перед ними сформировать target/test-classpath.txt через `mvn dependency:build-classpath -Dmdep.outputFile=target/test-classpath.txt`. Пользовательскому запуску эти инструменты не нужны.

Отчёт именно этой финальной сборки: **docs/FINAL_VERIFICATION.md**. Список восстановленных файлов: **docs/FINAL_CHANGES.md**. Проверка целостности файлов пакета: MANIFEST_SHA256.txt.

## Что включено и исключено

Включены готовые WAR, исходники и тесты, схемы/миграции, скрипты подготовки/запуска, локальные веб-ресурсы, PDF-шрифт и необходимые инструкции.

Исключены `.idea`, `.git`, `*.iml`, target, node_modules, личная local-run, пароли/ключи, логи, временные файлы, старые интеграционные ZIP/патчи, устаревшие инструкции и Docker-конфигурация. Развёрнутые приложения, ключи и служебные файлы создаются уже при запуске на вашей машине.
