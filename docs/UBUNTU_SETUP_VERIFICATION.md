# Проверка Linux-подготовки

Проверено в Linux без Docker: Bash/Python 3, JDK 17, отдельные PostgreSQL 13.16
и 17.11, шесть нативных Tomcat 10.1.61. Использованы peer/socket-доступ текущего
владельца тестового кластера (--no-sudo) и режим пароля администратора по TCP.
Стандартный Ubuntu sudo/peer-вход реализован через sudo -u postgres и описан в
UBUNTU_NO_DOCKER.md; изменение настроек системного PostgreSQL не требуется.

Результаты:

- Первый запуск на PostgreSQL 13 и 17: пять БД, таблицы, данные примеров,
  версии миграций, ключи и шесть наборов окружения — PASS.
- С настройками генератора запущены все шесть приложений: регистрация,
  User/Moderation, nearest, права на position, finish/pay, PDF-чек/история,
  снимок, запрет чужого доступа, soft delete, logout/отзыв — PASS.
- Служебная PostgreSQL-роль не superuser; её прав владельца проектных БД
  достаточно для запуска и операций сервисов.
- Повтор после поездки сохраняет зарегистрированных пользователей, PAID,
  документы, пароль роли и все три файла ключей — PASS.
- Все шесть env.sh загружены Bash; значения совпали с env.json — PASS.
- Файлы окружения/реквизитов на тестовой Linux FS имеют права 600.
- Изменённая контрольная сумма применённой миграции отклоняется с понятной
  ошибкой; тестовое изменение восстановлено, данные не удалены — PASS.
- Отсутствующий шрифт, неверный сохранённый пароль и параллельная подготовка
  отклоняются; исходные реквизиты восстановлены тестом — PASS.
- Режим пароля администратора работает без sudo; пароль администратора не
  попал в linux-database.json — PASS.
- Bash-синтаксис, Python-компиляция и CLI --help проверены.

Основной запуск и ручная проверка не требуют Node.js. Для автоматического
сценария после готовности стенда использован scripts/check-native-stack.cjs.
Сценарий создаёт тестовые аккаунты/поездку/документы; выполняйте его на тестовом
стенде. GitHub Actions дополнен первым и повторным запуском Linux-подготовки,
фактический удалённый статус следует смотреть в Actions.
