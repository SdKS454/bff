# Отчёт подготовки к сдаче — 27 октября 2026

Проверяется весь репозиторий: BFF/ScootX и пять самостоятельных сервисов в services/.
Контекст всех приложений `/`, сайт localhost:8080, сервисы 8081–8085.
Отдельных обязательных требований преподавателя нет; объём определяется проектом,
исходным брифом, сохранёнными REST-контрактами и согласованной учебной оплатой.

## Что завершено

- Сквозная регистрация с общей валидацией, вход, профиль, отзыв JWT, USER/ADMIN.
- Каталог/nearest и защищённое резервирование самоката; защита от двойной аренды.
- Старт, обновление позиции активной поездки, завершение, снимок тарифа,
  идемпотентная учебная оплата 50 ₽ + 8 ₽/начатая минута, минимум одна минута.
- Блокировки/разблокировки через административную панель и User → Moderation.
  Бан запрещает новый старт, но не мешает завершить и оплатить текущую поездку.
- Три настоящих PDF с кириллицей. История генераций, собственные метаданные,
  повторное скачивание из сохранённого JSON-снимка и мягкое удаление.
- Сохранение исторического содержимого PDF после новых поездок/снятия бана.
  Старые записи без снимка восстанавливаются только из доступных источников.
- Восстановление незавершённых межсервисных операций после сбоя/перезапуска.
  Служебные операции не зависят от срока пользовательского JWT.
- Миграции существующих БД в Compose: версии, транзакции, advisory lock,
  проверка SHA-256. Обычное обновление не требует удаления volumes.
- Исправлены поздние переходы в закрытый кабинет, потеря дат формы при загрузке
  документов и повторное открытие формы входа из устаревшего auth URL.
- Подготовлены демонстрационные аккаунты по явному запуску prepare-demo.cjs,
  автоматический workflow и отдельные сценарии проверки реального стенда.

## Принятые решения

Все 21 тема исходного документа сохранены и имеют решение в API_CONTRACTS.md.
Для сдаваемого стенда используются дробные координаты учебной евклидовой сетки
в диапазоне ±1000000; distance в единицах сетки. Геолокация не смешивается с сеткой.
Профиль только для просмотра, избранное локальное и раздельное по пользователю.
Панель ADMIN обращается прямо к User с Bearer/CORS; дублирующий BFF-прокси не нужен.
Бессрочный PAYMENT_DEBT снимается ADMIN вручную по исходному правилу.
PDF создаёт Thymeleaf + OpenHTMLtoPDF, бинарные файлы не хранятся.
Оплата учебная, настоящего списания и платёжного провайдера нет.

Итого **344 автоматические проверки**. Scooter собирается Maven; его поведение
проверяется сквозными сценариями настоящего стенда, отдельной unit-сюиты нет.
В HTTP-регрессии BFF downstream заменены фикстурами; сквозные сценарии ниже
используют все настоящие приложения и пять отдельных БД.

На новом отдельном Compose-проекте kicksharing-full-check-submission проверена
инициализация с пустыми БД и ключами. На предыдущем проекте проверено обновление
схемы 26 октября без удаления данных. Финальная сборка использует Servlet 6.0;
предупреждение о старом descriptor 6.1 в Ride устранено.

- check-full-stack.cjs — PASS: все настоящие сервисы/БД, конкуренция, тарифный
  снимок, учебная оплата, русские PDF, бан/разбан, остановки Scooter/Moderation,
  перезапуски Ride/User, браузерный USER/ADMIN и отзыв во всех шести приложениях.
- check-submission.cjs — PASS: границы координат на BFF/Scooter/Ride, активная
  позиция, снимки чеков/истории/уведомлений, история с пагинацией, чужой доступ,
  soft delete, восстановление FAILED и повторные миграции. Браузер: повторное
  скачивание/удаление, даты формы, отмена и редактирование позиции.

Исправленная в ходе прогона ошибка: пустой DELETE без Content-Length получал
415. Регрессия теперь проверяет настоящий HTTP-запрос без длины/тела; chunked
запрос с неверным Content-Type по-прежнему получает 415.

В одном предварительном сквозном прогоне возник единичный тайм-аут загрузки
строки ADMIN-панели. Отдельная диагностика панели и повторный полный прогон
прошли без изменения серверного поведения. Причина единичного сбоя не установлена;
скрипт теперь сохраняет скриншоты и текст страниц при сбое. Это ограничение
воспроизводимости теста, а не подтверждение безошибочности на любом компьютере.

- check-stack-recovery.cjs — PASS: постоянная отмена резервации, идемпотентный
  reserve, защита новой поездки от старого release, восстановление прерванного
  STARTING после отзыва JWT. Полный down/up сохранил БД, RSA-ключи, действующие
  токены, PAID/paidAt/суммы и возможность генерировать PDF.
- prepare-demo.cjs — два последовательных запуска PASS на тестовом проекте:
  USER demo.user и ADMIN demo.admin, без сброса существующих паролей/данных.

Все три сквозных сценария завершились с кодом 0. Для ключевого сценария аренды
после единичного тайм-аута выполнен повторный полный успешный прогон.
Проверка REST-документа: все 21 исходная тема и 47 прежних ссылок method/path
сохранены. Архив исходного MD не изменён (SHA-256
