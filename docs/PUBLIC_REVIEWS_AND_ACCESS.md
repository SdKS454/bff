# Реальные отзывы на главной, вход по сессии и служебные адреса

Обновление поверх `temp/reviews-validation`, `930306f`.

## Что изменилось

- Главная получает настоящие сохранённые отзывы из Ride через BFF. Старые демонстрационные отзывы удалены. Показываются оценка поездки, оценка самоката, оба комментария и дата. Автор обозначен «Пользователь ScootX»; логин, UUID, номер самоката, координаты, сумма и другие данные поездки не публикуются.
- Последние два отзыва показаны сразу, «Все отзывы» загружает страницы по 20. Есть пустое состояние, ошибка, повторная загрузка. После сохранения/изменения отзыва главная обновляется. HTML комментариев выводится как текст.
- Публичный GET `/api/reviews?limit=20&offset=0` есть у BFF 8080 и Ride 8084. Допустимы limit 1–100 и offset >= 0. Сортировка по reviewedAt DESC, id DESC. Защищённые ручки поездок/изменения отзывов остаются защищёнными.
- `login.jsp` ведёт на `/auth/entry`. Без действующей сессии открывается вход, при USER — профиль, при ADMIN — панель с текущим JWT во fragment. GET не отзывает токен и не удаляет сессию. При недоступном User показывается ошибка зависимости, а не ложный успешный вход.
- При вводе служебного API-адреса в адресной строке браузера вместо JSON показывается HTML-страница с кодом 403 и ссылкой на сайт. Учтены browser navigation и Accept: text/html. BFF закрывает такую навигацию на `/api/*`; остальные сервисы — в своих обработчиках/фильтрах. Публичная HTML-страница админки по-прежнему открывается, а данные и действия требуют ADMIN. Корни Scooter/Documents могут по-прежнему возвращать стандартную HTML-404: пользовательских главных страниц там нет.

## Какие права у USER и ADMIN

Основной пользовательский сайт — `http://localhost:8080/`. Панель ADMIN — `http://localhost:8082/admin/users.html`, вход через BFF login.jsp. Остальные порты — API сервисов.

Сам факт получения JSON **не означает** доступа к администраторским данным. Авторизованному USER необходимы API своего профиля/поездок/документов и каталога. Публичную ленту отзывов можно читать без авторизации. Список всех пользователей, причины/список блокировок и ban/unban требуют ADMIN; чужие профили/поездки/документы проверяются по владельцу.

Страница «Служебный адрес» ограничивает навигацию браузера, **не заменяет авторизацию и не изолирует порты сетью**. API-запросы из приложения или Postman с Accept: application/json продолжают работать в пределах прав токена. Нельзя считать изменение Accept повышением роли: запросы к чужим/административным данным по-прежнему получают 403. Для сетевой изоляции production-системы нужен отдельный reverse proxy/firewall; в текущем локальном стенде сервисы запускаются на отдельных localhost-портах.

## Как поставить точечно

1. Остановить все шесть приложений.
2. Скопировать файлы из ZIP обновления с объединением папок. Точный список — `CHANGED_FILES_PUBLIC_REVIEWS.txt` в ZIP. Новые классы добавить, одноимённые заменить. Свой `local-run` сохранить.
3. Пересобрать и заново развернуть **все шесть приложений**, поскольку обработка навигации добавлена на каждый сервис. Использовать прежние env.txt и порты. Новых переменных окружения и зависимостей Maven нет.
4. Для этого обновления новых SQL-миграций нет. Ранее добавленная `local-stack/migrations/ride/002_reviews.sql` должна быть уже применена. Публичная лента использует те же сохранённые оценки/комментарии.
5. Перезапустить приложения и обновить BFF через Ctrl+Shift+R.

Если при сборке старой локальной версии ещё возникает `review(...) does not override`, проверь, что в `RideRepository` остался метод `boolean review(UUID id, ru.itis.model.RideReview review);` из предыдущего обновления. Новая публичная лента сама этот интерфейс не меняет.

## Что проверить

1. Сохранить отзыв после завершения поездки и открыть главную в инкогнито: видны обе оценки и комментарии. Изменить отзыв: обновилась та же запись. Пустой список не заменяется придуманными отзывами.
2. Открыть «Все отзывы», проверить следующую страницу, повтор и закрытие во время загрузки. При остановленном Ride должна быть явная ошибка, не фиктивные отзывы.
3. Войти USER и открыть login.jsp: кабинет, без повторного пароля и без logout. Войти ADMIN: панель; снова открыть login.jsp: панель по действующей сессии. Без токена/сессии панель ведёт на вход.
4. Ввести в адресной строке `/api/users/me` на 8080, API модерации на 8082, `/api/rides` на 8084: 403 HTML со ссылкой на сайт. Работа интерфейса после возврата продолжается.
5. В Postman использовать Accept: application/json. USER читает свой профиль/каталог/поездки; список всех пользователей, справочник модерации и чужой профиль — 403. Без JWT личные ручки — 401. Public `/api/reviews` — 200 без JWT и только пять разрешённых полей.

Обновлённые полный чек-лист, CSV и Postman находятся в `docs/`.

Все шесть Maven-сборок прошли; Java — 345 тестов (включая настоящие HTTP/БД-тесты User), JavaScript API — 8 тестов, Chromium — 31 сценарий. На настоящем локальном стенде из шести сервисов проверены публичный JSON без личных полей, создание/редактирование реального отзыва, переходы USER/ADMIN по сессии, запреты USER на список пользователей/причины/чужой профиль, HTML-отказ навигации на всех шести API, а также поездка/позиция/отзыв/оплата/PDF/снимки/удаление/отзыв JWT. Полный ручной чек-лист содержит 331 пункт и 60 операций API; его результаты на пользовательском ПК ещё требуется заполнить.
