# Работа без разрешения на геолокацию

Обновление поверх `temp/reviews-validation` / `9144c4a`. Сервисы и БД не меняются.

## Поведение

- При отказе, тайм-ауте или отсутствии геолокации загружается настоящий общий каталог Scooter (`GET /api/scooters`). Показаны все статусы; начать поездку можно на READY-самокате. Расстояния скрыты, сортировки по близости нет. Причина и режим каталога указаны на странице.
- «Обновить каталог» продолжает работать. При переходах по аккаунту сайт не запрашивает геолокацию снова после уже полученного отказа. «Повторить геолокацию» позволяет попробовать снова после изменения разрешения. Браузер сам управляет показом диалога разрешений; сайт не может отменить установленный пользователем запрет.
- Начало поездки доступно без геолокации. Перед стартом запрашивается актуальная карточка выбранного самоката; в start posX/posY передаётся его настоящая позиция из базы, а не придуманное местоположение пользователя. Этот режим объясняется в форме. При отсутствии корректной позиции или доступности самоката старт отклоняется.
- При завершении сначала пытаемся определить актуальное местоположение. Если не получилось, владелец может отдельно подтвердить завершение по сохранённой позиции поездки (последнее обновление позиции, иначе позиция старта). Кнопка доступна только при наличии корректных координат. Пользователь видит предупреждение об устаревшей позиции и подтверждает её отдельным диалогом. Отмена не завершает поездку. Если сохранённых координат нет, нужно разрешить геолокацию.
- Повтор после ошибки завершения использует ту же первую подтверждённую позицию, сохраняя совместимость с идемпотентностью Ride.
- Профиль, история, отзывы, оплата и документы остаются доступны без геолокации.
- При недоступности Scooter показывается ошибка сервиса. Демо-каталог и координаты пользователя не подставляются.

Это режим существующего локального проекта. Без датчика или разрешения невозможно подтвердить фактическое место окончания поездки — пользователь подтверждает последнюю сохранённую позицию.

## Точечная установка

Остановите BFF. Замените в своём проекте только:

```text
src/main/webapp/frontend/account.js
src/main/webapp/index.jsp
```

Пересоберите и повторно разверните BFF, перезапустите его, обновите страницу через Ctrl+Shift+R. Ключи, переменные окружения и базы данных менять не нужно. Остальные пять сервисов остаются прежними.

В Git дополнительно обновлены только браузерные проверки и их тестовый сервер:

```text
src/test/browser/scootx.test.cjs
src/test/java/bff/BrowserTestServer.java
```

## Проверка вручную

1. Запретить геолокацию и войти: появился каталог, нет расстояний, есть объяснение и кнопка повторной попытки.
2. Открыть профиль, историю, документы и избранное: всё доступно, сообщение каталога не пропадает при переключении избранного.
3. Начать поездку на свободном самокате: успешно, начальная позиция соответствует выбранному самокату из БД.
4. Завершить при запрете: показана ошибка геолокации и вариант завершения по сохранённой позиции. Отменить подтверждение: поездка остаётся активной. Подтвердить: поездка завершается и доступна оплата.
5. Разрешить геолокацию в настройках браузера, нажать «Повторить геолокацию»: вернулись ближайшие и расстояния, кнопка скрылась.
6. Проверить тайм-аут геолокации: доступен общий каталог. Выключить Scooter: видна ошибка сервиса, фиктивных самокатов нет.

Проверено: Maven BFF — 96 тестов (включая 47 HTTP), Chromium — 25 сценариев. В браузере проверены отказ в геолокации, настоящий каталог без расстояний, начало по позиции самоката, отмена/подтверждение завершения по сохранённой позиции, повторное разрешение геолокации и ошибка Scooter. Браузер использует настоящий упакованный BFF и HTTP-заглушки внешних сервисов; весь набор из шести сервисов для этой фронтенд-правки повторно не запускался.
