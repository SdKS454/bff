# Интеграция ScootX и BFF

> Обновление 26 октября: полный актуальный стенд и исходники всех сервисов —
> `services/` и [инструкция запуска](../local-stack/README.md).
> Ниже сохранена предыдущая сверка; сведения о фикстурах относятся к её дате.

## Источник

Использован предоставленный `ScootX 3.zip`. В исходном макете все действия
выполнял `demo-storage.js`, включая хранение локальных пользователей, хешей
паролей, сессий, поездок, расчёт тестовой цены/заряда/дистанции. Сетевых запросов
не было. README/BACKEND_GUIDE архива использованы как описание макета, а не
как инструкции менять backend-контракты.

Сохранены оформление, изображения, локальные шрифты, каталог, модальные формы
и кабинет. Приложение отдаётся тем же WAR и с того же origin, что и BFF.
`index.jsp` — основная страница; файлы оформления и JS — `/frontend/`.
Старые JSP-адреса совместимы через перенаправления на параметры экрана.

## Изменения по функциям

| Функция | Реализация |
| --- | --- |
| Регистрация | Реальный POST `/api/auth/register`; актуальные правила User, в том числе 72 байта UTF-8. Затем отдельный login, как в макете; если он не удался, открывается форма входа с пояснением, повторной регистрации нет |
| Авторизация | POST login, HttpOnly-сессия BFF, GET me. Ни демо-JWT, ни пароли/токены в хранилище браузера не используются |
| ADMIN | GET `/api/config`, редирект на доверенный настроенный URL Moderation с токеном в fragment, без токена в query |
| Каталог/карточка | GET `/api/scooters`, GET `/api/scooters/{numberPlate}`; данные backend, без фиктивного парка при 401/503 |
| Ближайшие | POST `/api/scooters/nearest`, числовые координаты из формы; distance не выдаётся за запас хода |
| Старт | POST `/api/rides`, реальные numberPlate и введённые координаты. Проверка бана и конфликта также остаётся на BFF/Ride |
| Завершение | PUT `/api/rides/{UUID}/finish`, координаты конца; итоговую сумму считает Ride |
| Оплата | POST `/api/rides/{UUID}/pay`; PAID показывается только по данным сервиса. Отказ не создаёт локальной оплаченной поездки, есть повтор |
| История | GET `/api/rides`, только история текущего пользователя; отображается ACTIVE/FINISHED/PAID |
| Документы | POST `/api/documents/generate`: RIDE_PAYMENT для PAID, USER_HISTORY за период, USER_BLOCKED для заблокированного профиля; скачиваются PDF-байты |
| Выход | POST `/api/auth/logout`, отзыв через User и закрытие BFF-сессии. Ошибка отзыва показывается пользователю |
| Профиль | Только чтение GET me. Нет фальшивой кнопки «Сохранено», поскольку согласованного write API нет |
| Избранное | Локальные номера на устройстве, отдельный ключ для userId. Об этом написано в кабинете; эта функция не притворяется серверной |

Из UI удалены тестовые 50 ₽/8 ₽, 30 км запаса хода, имитация движения/разряда,
выдуманные адреса и тестовая оплата. Активная сумма без amount от сервиса
показывается как ещё не рассчитанная. Локально обновляется только таймер
времени по startedAt; он не рассчитывает оплату. Заряд — последний ответ Scooters,
а не расчёт фронта. Фото иллюстративные, как в предоставленном дизайне.

## Ошибки и защита

- Статус и текст JSON-ошибок BFF показываются в форме/уведомлении. HTML ошибки
  proxy не вставляется как разметка. Ошибки API не подменяются демоданными.
- Ошибка каталога не мешает открыть профиль; ошибка истории видна отдельно.
  При 401 приватное состояние очищается и доступен вход.
- Строки сервисов экранируются перед вставкой в разметку; числовые значения
  проверяются, charge ограничен диапазоном 0–100 перед использованием в CSS.
- Номер самоката кодируется один раз для path. UUID поездок не приводятся к числу.
- submit блокируется на время запроса. После подтверждённого действия ошибка
  обновления данных не объявляет само действие неуспешным.
- В избранном сохраняются только номера. Данные демопользователей из старого
  макета не мигрируют в реальные учётные записи.

## Границы

User, Scooters, Ride, Documents и Moderation — отдельные проекты; в BFF они
не вшиваются. Их адреса/порты настраиваются как ранее. Настоящие списания,
резервация самоката и расчёт тарифа — ответственность сервисов.

Единицы координат всё ещё должны согласовать команды. Нет округления или
выдуманного перевода градусов в сетку. Геолокация по отдельной кнопке даёт
X=longitude, Y=latitude, и пользователь может ввести другие координаты вручную.
Единицы distance не подписаны как метры.

Сохранена настольная вёрстка архива (min-width 1080 px); мобильная адаптация
не добавлялась. Фронт не содержит собственной панели Moderation; её фактический
путь команда должна подтвердить. Локальный default остаётся
http://localhost:8082/admin/users.html и может переопределяться.

## Воспроизведение

1. `mvn clean verify` — собранный WAR и 85 backend-тестов.
2. `node --test src/test/js/*.test.cjs` — 6 проверок нового API-адаптера/валидации.
3. `npm ci`, `npx playwright install chromium`.
4. `mvn dependency:build-classpath -Dmdep.outputFile=target/test-classpath.txt`.
5. `npm run test:e2e` — 14 сценариев настоящего браузера против BFF WAR и
   управляемых тестовых HTTP-сервисов, включая негативные исходы.

При наличии Chrome можно вместо установки браузера указать CHROMIUM_EXECUTABLE.
Тестовые BrowserTestServer и downstream-заглушки находятся только в test sources,
не включаются в production WAR и не становятся fallback-режимом приложения.

## Фактический результат

Пройдены все 85 Java-тестов (42 unit + 43 HTTP), 6 unit-проверок фронта и
14 сценариев настоящего браузера — 105 проверок, без ошибок и пропусков.
Использованы Playwright 1.62.1 и Google Chrome 155.0.8059.84.
Проверены также отображение страницы/кабинета и загрузка всех локальных ресурсов.

Дополнительно новый интерфейс открыт против настоящих WAR BFF и User Service
с PostgreSQL 16: через браузер зарегистрирован пользователь, выполнены вход
с настоящим RS256 JWT, профиль, аренда/завершение/оплата/PDF и выход. После
выхода настоящий User `/api/users/validate` вернул 401 для выданного токена.
В этом прогоне только User и PostgreSQL были настоящими: Scooters, Ride,
Documents и Moderation заменены HTTP-заглушками. Реальные разблокировка
самоката, расчёт/списание денег и доступность панели этим не подтверждены.
Временные серверы и PostgreSQL после проверки остановлены.
