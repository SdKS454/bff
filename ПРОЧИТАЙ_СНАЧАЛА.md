# Небольшая ручная GPS-правка

В ветке temp/gps-update эта правка уже внесена в полный проект. Можно собирать
исходники из скачанного ZIP ветки. Если обновляете существующую настроенную копию,
ниже перечислены заменяемые файлы и порядок точечного обновления.
БД, ключи, пароли и конфигурации IDEA не включены в Git-архив.

## Что меняется в приложении

Три рабочих файла:

1. src/main/webapp/frontend/account.js — удалены ручные поля координат; после
   входа автоматически запрашиваются GPS и ближайшие READY-самокаты из API;
   старт/позиция/завершение получают координаты браузера. Закрытая форма не выполняет
   запоздалое действие. Повтор finish после сбоя сохраняет исходную позицию попытки.
   Убраны надписи об учебном режиме в интерфейсе.
2. src/main/webapp/frontend/script.js — местоположение обозначено как долгота/
   широта, расстояние показано в метрах/километрах.
3. services/scooter/src/main/java/ru/itis/repository/Scooters.java — nearest
   считает расстояние по формуле гаверсинусов вместо евклидовой сетки. Сортировка
   по расстоянию, при равенстве — номер. Неверный GPS nearest получает 400;
   некорректные GPS-точки самокатов в БД — ошибку вместо выдуманных расстояний.

Дополнительно включены обновлённые browser/географические тесты и два сценария
приёмки. Их нужно копировать вместе с рабочими файлами, если используете автотесты.

## Применение

1. Сохрани копии заменяемых файлов своего проекта.
2. Останови BFF и Scooter.
3. Скопируй из этого архива src/, services/ и scripts/ в корень своего проекта
   с заменой совпадающих файлов. Папки объединяются, остальные файлы остаются.
   Не удаляй старые src/services целиком.
4. Пересобери артефакты BFF и Scooter (Build → Build Artifacts → Rebuild).
   Если запускаешь через External Source, укажи новые собранные WAR, а не прежние
   скачанные WAR. Другие приложения и их настройки менять для этой правки не нужно.
5. Запусти Scooter, затем BFF; войди заново после перезапуска BFF и нажми Ctrl+F5.
6. Открывай http://localhost:8080/ и разреши браузеру геолокацию.

Локальная папка local-run, переменные окружения, порт PostgreSQL 7689, RSA и
SERVICE_API_KEY сохраняются. SQL-схему пересоздавать не требуется.

## Обязательно: координаты самокатов теперь географические

posX / position_x = longitude (долгота, -180..180).
posY / position_y = latitude (широта, -90..90).
Поле distance ближайших теперь в метрах, по прямой по поверхности Земли.

Старые демонстрационные точки X=10, Y=15 — не точки твоего города. Они будут
интерпретированы как реальные 10° долготы, 15° широты и могут оказаться очень далеко.
Чтобы проверить самокаты рядом с собой, внеси в scooter реальные GPS-точки вашего
города. Это изменение координат строк, а не создание БД заново. Не перемещай
самокат, который сейчас IN_RIDE.

Для проверки через DevTools можно явно задать тестовую позицию в Sensors рядом
с известными точками БД. Это тестовый источник позиции, а не реальная геолокация
пользователя. В обычном режиме приложение не подставляет фиктивные координаты.
Если разрешение отклонено/геопровайдер недоступен, показывается ошибка и повторная
попытка после исправления разрешений. Ручных полей X/Y нет.

nearest возвращает реальные свободные самокаты из БД, отсортированные от ближайших.
Радиус поиска не ограничен: если в БД нет точек вашего города, могут показаться
ближайшие из имеющихся, но далеко. Расстояние не является дорожным маршрутом.

- 5 JUnit-тестов Scooter: нулевое расстояние, метры на экваторе, географический
  порядок около полюса, линия перемены дат, антиподы, отклонение неверного GPS — PASS.
- Scooter собран Maven verify с Java 17 — BUILD SUCCESS.
- Обновлённые check-full-stack.cjs и check-submission.cjs проверены синтаксически;
  полный прогон всех шести реальных сервисов с этой правкой ещё не выполнен.

не подключает платёжного провайдера. Серверный paymentMode и учебная пометка
в PDF остаются для корректного отражения фактического способа оплаты.
